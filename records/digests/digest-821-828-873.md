# Digest: #821, #873, #828 (light-dark() lowering and color-scheme)

| Issue | Type | Status | Severity | Action | Summary |
|---|---|---|---|---|---|
| #821 | bug | confirmed | high | needs-maintainer-decision (review PR #1287) | Polyfilled light-dark() inside custom properties resolves where the token is declared (:root), so a descendant's color-scheme doesn't flip it. Browser-confirmed; Calcite, react-data-grid, Vite 8 users affected. |
| #873 | bug | duplicate of #821 | high | link-duplicate | `dark only` order and the prefers-color-scheme idea are works-as-intended; the real follow-up case (theme classes on descendants) is #821's root cause. |
| #828 | question | works-as-intended | low | close | Toggles can already be disabled with `exclude: Features.LightDark` or native targets; custom names declined in #708. |

## Shared root cause

Yes for #821 and #873: the `var(--lightningcss-light,a) var(--lightningcss-dark,b)` technique is substituted at the element that declares a custom property, while native light-dark() in a custom property stays unresolved until use. Any design-token setup (tokens on :root, color-scheme switched on a subtree) breaks. #828 is the same mechanism seen from the other side (people want the toggles gone, often because of this bug) but needs no code change.

Fix direction (maintainer decision): PR #1287's second iteration (keep the polyfill, add `@supports (color: light-dark(...))` native overrides for custom properties). Hand-built output in that shape is browser-equivalent to native on the #873 fixture (Chromium, light and emulated dark). Review it for its extra, unrelated changes (supports-scope include flipping, attr() detection, @property initial-value) and size cost. Alternative the maintainer floated: a separate flag for vars. Either way, the docs caveat promised in #821 (2026-06-24) is still missing from website/pages/transpilation.md.

Side findings: `color-scheme: inherit` -> `normal` (comment on #821) fixed by #1152, released in 1.32.0. The Rust example in #821's comments passes targets only to `to_css`, not `minify`, so no toggles are emitted (usage error).
