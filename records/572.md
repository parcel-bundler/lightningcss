# #572 Properties order not maintained

**bug, confirmed, high, keep-open (umbrella).**

- Original case (`animation` + `animation-timeline`) is now worse than reported. Since 1.25.0 (f4408c7) the timeline is folded into the shorthand: `.item{animation:both fade scroll(root)}`. Chromium 153 rejects that (`parse()` = ''), so the computed `animation-name` is `none` and the animation is gone. This happens with no targets and with Chrome >= 115 targets. The reason is that `animationTimelineShorthand` in `scripts/build-prefixes.js` comes from a BCD entry that is `partial_implementation` (reset-only) in Chrome. It is tracked separately in #1283, #1342 and #1369, with PR #1306.
- `transition`/`transition-behavior` and `animation`/`animation-composition`: the longhand moves before the shorthand on every version. equivalence.mjs reports NOT EQUIVALENT. Tracked in #1084, with PR #1365.
- `height:60px;height:var(--h)` and `block-size:auto;block-size:calc-size(auto)`: fixed in 1.28.0 (22a8b6f, bisected 1.27.0 → 1.28.0).
- Still broken on master and tracked elsewhere: `font` + `font-variant-numeric` (#1207), `caret` (#1362), `position:static;position:var()` (#1225, PR #1387).
- `font-weight`/`font-variation-settings` reordering: probably harmless, since these are independent properties (not browser-verified).

Suggested: keep it open as the umbrella, post a status comment linking the sub-issues, and prioritise PR #1306, which fixes silent loss of the whole animation.

## Draft reply

Thanks all. A status update, since this thread now covers several different bugs:

- **animation + animation-timeline (the original report):** since 1.25.0 the timeline is folded into the shorthand (`animation:both fade scroll(root)`). No browser accepts a timeline inside `animation` yet (Chrome's support is reset-only), so the whole declaration is dropped. Tracked in #1283 / #1369, with a fix proposed in #1306.
- **transition-behavior / animation-composition after the shorthand:** #1084, fix proposed in #1365.
- **width/height/block-size with var() or calc-size():** fixed in 1.28.0.
- `font` + `font-variant-*`: #1207; `caret`: #1362; `position`/`direction` with var(): #1225.

If you hit a case not in that list, please open a new issue with a minimal input and output so each one can be fixed and tested on its own.
