# #1176 Support container-type: anchored and @container anchored()

**feature, feature-request, medium, needs-maintainer-decision (review PR #1218).**

- Confirmed on master and on 1.31.1 through 1.33.0. In strict mode, `@container anchored(fallback: flip-block)` errors with `Unexpected token Function("anchored")`. With `errorRecovery`, the rule is kept verbatim and a warning is emitted. `container-type: anchored` is silently kept as unparsed.
- Spec: css-anchor-position-2 ED (`<query-in-parens> = ... | anchored(<anchored-query>)`, `fallback: none | [<dashed-ident> || <try-tactic>] | <position-area-query>`). `container-type` keywords combine (`anchored inline-size`).
- Support (BCD 8.0.7): Chrome/Edge 143. Firefox and Safari: no. Marked experimental. This is the same status as `scroll-state()`, which is already supported unflagged, so it fits the existing precedent. A draft flag could be argued for, since only one engine ships it.
- Impact: 21 reactions, duplicate #1228, and it blocks Next.js/Turbopack and Parcel builds.
- PR #1218 addresses both of devongovett's review comments (bitflags `ContainerType`, typed fallback value). It changes the `ContainerType` AST shape, from a string to `"normal" | flag[]`, which is a breaking change for JS visitors. It also skips `<position-area-query>`.
- Side finding: unknown query functions (`@container foo(x)`, `@media foo(x)`) are hard errors, even though the grammar allows them as `<general-enclosed>` and Chromium keeps them. This conflicts with "unknown-but-valid syntax passes through". It might deserve its own issue.

Repro: `1176-repro.mjs`; output: `1176-repro-output.txt`.

## Draft reply

Thanks for the report. Confirmed: `@container anchored(fallback: ...)` currently fails to parse (master and 1.33.0), and `container-type: anchored` is passed through without being understood. The syntax is in the css-anchor-position-2 draft (https://drafts.csswg.org/css-anchor-position-2/#container-rule-anchored) and shipped in Chrome 143. Firefox and Safari don't have it yet.

There's an open PR implementing it (#1218) that is waiting on review. Until it lands, enabling `errorRecovery: true` turns the error into a warning and keeps these rules as written in the output.
