# #202 nesting rules not transformed correctly when targeting older browsers

**feature / feature-request / low / needs-maintainer-decision**

With a multi-selector parent (or a complex parent with & not leftmost), nesting is lowered to `:is(...)` regardless of targets, and no warning is emitted when targets lack :is(). Per the nesting spec `&` has :is() semantics (matching and max specificity), so :is() is correct in general and a naive expansion is not. But some cases can be lowered exactly (e.g. `.foo, .bar { & .baz }` -> `.foo .baz, .bar .baz` when all parents have equal specificity), and the remaining cases deserve a warning, as esbuild does.

## Draft reply

Still current on 1.33.0: `.foo, .bar { & .baz {} }` becomes `:is(.foo, .bar) .baz` even for Chrome 55, with no warning. As discussed above, `&` is defined with `:is()` semantics, so `:is()` is the correct output in general, and expanding it can change matching or specificity (e.g. `.foo, #bar { & .baz {} }`).

Some cases could be lowered exactly, though: when all parent selectors have the same specificity, `.foo .baz, .bar .baz` is equivalent. For the rest, a warning when the targets don't support `:is()` would at least make the problem visible. Whether to do either is up to the maintainer; #1159 and #944 ask for the same thing.

Workaround today: for old targets, write the expanded selectors by hand or avoid nesting under selector lists.
