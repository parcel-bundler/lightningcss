Draft reply:

> This is expected when no browser targets are given: Lightning CSS then assumes a browser with full standards support and drops vendor-prefixed fallbacks, so `width: -webkit-fill-available; width: -moz-available; width: stretch` becomes `width: stretch`. With real targets all three are kept, e.g. `targets: browserslistToTargets(browserslist('defaults'))` gives `width:-webkit-fill-available;width:-moz-available;width:stretch`, and a lone `-webkit-fill-available` is never removed.
>
> In Vite, `build.target: 'esnext'` ends up passing empty targets when minifying CSS, as you found. Setting `build.cssTarget` to real browsers (for example `['chrome111', 'safari16', 'firefox115']`) should keep the fallbacks.
>
> Separately, `include: Features.VendorPrefixes` with `stretch` and no targets currently crashes in released versions (#1371). That's fixed on master and will be in the next release.
