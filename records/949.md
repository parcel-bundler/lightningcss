# #949 lightningcss ate my precision

**Status:** confirmed and long-standing (master, 1.14.0 and 1.33.0 identical). **Severity:** medium. **Action:** needs-maintainer-decision. #1394 has the same root cause (#917, closed, too).

All numbers print with 6 significant digits (cssparser's `dtoa_short`), so `1.3333333333` becomes `1.33333`, `33.333333%` becomes `33.3333%` and `calc(4/3)` becomes `1.33333`. This also applies to custom properties and unminified output.

The maintainer's earlier answer was that this matches browser serialization. That is true for CSSOM (Chromium shows `1.33333`), but Chromium lays out with more precision (Chrome 153, probe.mjs):

| value | layout result |
|---|---|
| 12px × `1.33333` | 15.984375px |
| 12px × `1.3333333333` | 16px |
| 12px × `1.3333334` (shortest f32 round-trip) | 16px |
| `33.3333%` of 300px | 99.984375px |
| `33.333333%` / `33.333332%` of 300px | 100px |

`equivalence.mjs --minify` reports NOT EQUIVALENT on the fixture. So the transform changes rendering, and the reported 1px shifts are real. The fix is to print the shortest decimal that round-trips the f32 (medium size, plus many expected-output updates and a few bytes per long number). An opt-in precision option is the alternative.

Repro: `949-repro.mjs`; browser fixture `949-in.css` / `949-fixture.html`, result `949-equivalence.txt`.

## Draft reply

Thanks, and thanks everyone for the extra cases. I checked this in Chromium: it serializes `1.3333333333` as `1.33333`, as noted above, but it lays out with more precision. With `font-size: 12px`, `line-height: 1.33333` gives a 15.984375px box where `1.3333333333` gives 16px. Likewise `33.3333%` of 300px is 99.984375px where `33.333333%` is 100px. So rounding to 6 significant digits can visibly change layout, which matches the 1px shifts reported here. Keeping enough digits to preserve the stored value (`1.3333334`) renders the same as the source. Whether to change the default number output is up to the maintainer. In the meantime, writing `calc(4 / 3)` doesn't help, because it gets folded to the same rounded value. #1394 covers the same root cause.
