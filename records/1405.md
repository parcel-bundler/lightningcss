# #1405: calc(NaN * 1px) prints as 5.10424e38px

**bug · confirmed · low · keep-open (or close, like #1397)**

Calc folding produces an f32 NaN. The serializers (`CSSNumber::to_css`, `serialize_dimension`) pass it to cssparser/dtoa_short, which has no NaN handling and prints the garbage value `5.10424e38`. css-values-4 says NaN at the top level is censored to 0. Chromium computes `margin-left: calc(NaN*1px)` as 0px, and `(min-width: calc(NaN*1px))` matches at every width while the output matches at none. Other affected cases: `opacity: calc(NaN)` (prints 5.1e38, browser gives 0), angles, `calc(NaN*1px + 1em)` (prints `calc(5.10424e38px + 1em)`, browser gives 0px) and `calc(infinity*0px)`. Properties wrapped in `NonNegative` already print 0 on master since #1329. It has been wrong in every release since 1.20 at least.

Real-world likelihood: ~nil, since nobody writes NaN in calc(). It's the same class as #1397.

Fix (small): print NaN as `NaN` inside calc and as 0 at the top level. Alternatively, add a single "top-level calc result" censor/clamp step, which would also cover #1397.
