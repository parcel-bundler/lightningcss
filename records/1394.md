# #1394: Numbers print with six significant digits, which changes values written with more and prints `10e-23`

**bug / duplicate / low / link-duplicate** (duplicate of #949)

Every number is printed with cssparser's 6-significant-digit serialization, so 1234.5678px -> 1234.57px and 99999.99px -> 100000px. Same root cause as #949. The only new detail is cosmetic: a value that rounds up across a power of ten in exponent form prints `10e-23px` instead of `1e-22px` (valid CSS, Chromium reads it back as 1e-22px, just 1 byte longer); no realistic stylesheet has such values.

## Draft reply

Thanks for the detailed report! This is the same root cause as #949, so I'll close this in favor of that issue to keep the discussion in one place.

The 6-digit serialization matches how CSSOM serializes numbers, but browsers compute at higher precision, so rounding can shift layout slightly. The direction discussed in #949 is not to print more digits, but to keep the expression when rounding would lose information, e.g. keep `calc(100% / 3)` instead of printing `33.3333%`. That is shorter and exact.

The `10e-23px` output is valid CSS (browsers read it as `1e-22px`), only a byte longer, and only happens for values far below anything a stylesheet would use.
