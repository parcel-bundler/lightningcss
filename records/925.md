# #925: `user-select` not prefixed for Safari

**Status:** fixed-in-release (1.29.3 and 1.31.0+) · **Severity:** high (historical) · **Action:** close

- **Regression:** 1.28.2-1.29.1 (and 1.29.2 / 1.30.x for Safari newer than their data). It came from compat data commit 4159bc5, which capped Safari UserSelect at `<= 18.1`. eccb673 moved the cap to 18.3. Current data is open-ended, which is correct: Safari still needs `-webkit-` through 26.5 (caniuse, MDN).
- **Repro:** `925-repro.mjs`, `925-repro-newer.mjs`. Local and 1.31.0+ output `pre{-webkit-user-select:all;user-select:all}`.
- **Maintainer note:** build-prefixes.js closes the range unless the *exact* latest caniuse version is listed. A mismatch between caniuse-lite copies (two in the old lockfiles, plus a removed `resolutions` pin) silently drops prefixes for new browser versions. A build-time assertion would prevent a repeat.

## Draft reply

Thanks for the report, and sorry for the slow reply. This was a problem in the browser compatibility data bundled with 1.28.2-1.29.1: for Safari, the `-webkit-user-select` prefix stopped at Safari 18.1, so Safari 18.2/18.3 got no prefix. The data was updated in later releases. With your targets, 1.31.0 and later (including the current 1.33.0) output:

```css
pre{-webkit-user-select:all;user-select:all}
```

Please upgrade to 1.31.0 or later. 1.29.2-1.30.2 can still drop the prefix for Safari versions newer than their data. I'll close this, but please reopen if you still see it on the latest version.
