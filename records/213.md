# #213 Negating custom media query breaks: confirmed bug, medium

**Status:** confirmed on master and all releases 1.14.0-1.33.0 (never worked). **Action:** queue fix (small).

`process_condition` in `src/media_query.rs` hoists a custom media's media type/qualifier onto the outer `@media` regardless of the surrounding `not`/`or`/`and`:

| input (`drafts.customMedia`, targets chrome 100) | output | correct |
|---|---|---|
| `--h: screen and (pointer: fine)`; `not (--h)` | `screen and not (pointer: fine)` | `not screen and (pointer: fine)` |
| same; `(--h) or (color)` | `screen and ((pointer: fine) or (color))` | `screen and (pointer: fine), (color)` |
| `--h: not screen and (color)`; `(--h) and (min-width: 2000px)` | `not screen and (color) and (min-width:2000px)` | needs an error, or a rewrite |

Chromium (print emulation / 1280px viewport) gives different matches for every pair. Spec: "The custom media query is evaluated logically, not treated as a textual substitution."

Fix: hoist the type only at the top level or a top-level AND term; for an entire-condition `not (--x)`, flip the qualifier; otherwise return the existing `UnsupportedCustomMediaBooleanLogic` error.

## Draft reply
Thanks for the report, and sorry for the slow reply. This still reproduces on the latest release (1.33.0) and on master: with `@custom-media --supports-hover screen and (pointer: fine)`, `@media not (--supports-hover)` compiles to `@media screen and not (pointer: fine)`, which only negates the pointer feature. You're right that it should be `not screen and (pointer: fine)`: [Media Queries 5](https://drafts.csswg.org/mediaqueries-5/#custom-mq) says a custom media query is evaluated logically, not substituted as text. The same problem shows up when a custom media with a media type is used inside `or`, or when one with `not` is combined with `and`. Until it's fixed, a workaround is to keep the media type out of the custom media and write it in the `@media` rule: with `@custom-media --fine-pointer (pointer: fine)`, `@media not screen and (--fine-pointer)` compiles to `@media not screen and (pointer: fine)` as expected.
