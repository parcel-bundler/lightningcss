# #747 Custom import resolvers in synchronous bundle()

**feature, feature-request, low, needs-maintainer-decision**

Native `bundle()` always reads from disk and silently ignores a `resolver` option (the TS types allow it only on `bundleAsync`). Repro with virtual files: sync gives `ERROR: No such file or directory`, with the resolver called 0 times. `bundleAsync` with the same resolver works. Same on master, 1.33.0, 1.32.0 and 1.31.1.

Why it's not trivial: the bundler loads imports in parallel on rayon threads (`src/bundler.rs`). `bundleAsync` reaches JS from those threads through threadsafe functions and channels, which deadlocks if the JS thread is blocked in a sync call. The WASM `bundle()` (`napi/src/lib.rs`, wasm32 module) already calls a synchronous JS resolver single-threaded, so the native fix could follow the same approach when a resolver is given. Size: medium.

Cheap first step: throw a clear error when `resolver` is passed to sync `bundle()`.

Workaround: `bundleAsync`, run synchronously in a worker if needed (e.g. Atomics.wait-based helpers). Related: #911 (built-in node_modules resolution).

Repro: `747-repro.mjs` (sync case plus a bundleAsync control).
