# #1049 logical border-radius removed when :where is present

**regression / confirmed / critical / queue-fix** (regression 1.29.3 -> 1.30.0, commit 6c465c1)

Since 6c465c1 (1.30.0, new nesting spec) declarations that follow a nested rule (or sit directly inside a nested @media) become a NestedDeclarationsRule. When targets need logical-property lowering, the handler moves the value into the context's ltr/rtl lists, but nothing emits them for that rule type: if no style rule follows they are lost; if a sibling nested rule follows (&:hover) they are emitted with that rule's selector. Expected: the physical :not(:lang(...)) / :lang(...) rules for the parent selector, in source order.

## Draft reply

Thanks, confirmed. This is a regression in 1.30.0 (1.29.3 is fine): declarations that come after a nested rule are now kept in their own block per the updated nesting spec, and the extra rules generated for logical properties are never emitted for that block. So the radius is lost when nothing follows, and when another nested rule follows (e.g. `&:hover`) it is attached to that rule instead (#1246). The same applies inside nested `@media` (#1023).

Minimal repro, targets Chrome 80:
```css
.btn1 { :where(&) { width: unset } border-start-start-radius: 4px }
```
Workarounds until it's fixed: put the declarations before the nested rules, or use targets that support logical properties. There is an open PR, #1386, that fixes the same problem for `@supports` color fallbacks in this spot; it could be extended to cover this.
