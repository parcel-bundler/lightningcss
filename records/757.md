# #757 CLI `This: command not found`

**bug, confirmed, medium, action: queue-fix (link #1193 as a duplicate)**

The npm bin of `lightningcss-cli` is a placeholder text file. `postinstall.js` overwrites it with the native binary from `lightningcss-cli-<platform>`. When install scripts don't run, the shell executes the placeholder text and fails with `This: not found`, exit 127. That happens with pnpm ≥ 10 by default, with Bun (it blocks untrusted lifecycle scripts) and with npm `--ignore-scripts`.

- **Reproduced:** `pnpm add -D lightningcss-cli@1.33.0` with pnpm 10.28.0 shows "Ignored build scripts", and the bin fails with exit 127. Adding `pnpm.onlyBuiltDependencies: ["lightningcss-cli"]` fixes it.
- **Repro file:** `757-repro.mjs` runs the checkout's placeholder with `sh`.
- **Duplicate:** #1193 (pnpm 1.32.0) has the same root cause.
- **Fix (medium):** make the bin a Node launcher that resolves and spawns the platform binary (esbuild's pattern). Keep postinstall only as an optimization. An interim alternative is a placeholder that prints an actionable message. The CLI is low-usage, but this breaks it entirely under the defaults of current package managers.

## Draft reply

Thanks for the report. This happens when `lightningcss-cli`'s install script doesn't run. The package ships a placeholder `lightningcss` file, and a `postinstall` script replaces it with the native binary for your platform. pnpm 10+ and Bun skip dependency install scripts by default (as does npm with `ignore-scripts`), so the placeholder text stays and the shell tries to run it as a command.

I reproduced it with `pnpm add -D lightningcss-cli@1.33.0` on pnpm 10.28. Until this is fixed, you can allow the script to run:

- pnpm: run `pnpm approve-builds`, or add `"pnpm": {"onlyBuiltDependencies": ["lightningcss-cli"]}` to package.json and reinstall
- Bun: add `"trustedDependencies": ["lightningcss-cli"]` to package.json and reinstall

A fix that doesn't depend on install scripts would make the CLI work out of the box. #1193 has the same cause.
