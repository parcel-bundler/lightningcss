# #592 Lower oklab/oklch with var() alpha

**Feature request, keep open, low.** Still unimplemented: `oklch(92.19% .04 20 / var(--o))` passes through unchanged for chrome 90 / safari 14 targets on master and 1.31.1–1.33.0. The same goes for oklab, lab and lch. `UnresolvedColor` in `src/properties/custom.rs` only covers rgb/hsl/light-dark. The `@supports` fallback machinery already exists for resolved colors in var()-containing values (`oklch(...) var(--y)` gets `#ffdbda` plus p3/lab blocks).

- Fix: medium. Add UnresolvedColor variants for lab/lch/oklab/oklch (and color()) with resolved components plus alpha tokens, then hook them into `get_necessary_fallbacks`/`get_fallback`. This is an additive AST union change.
- var() in the color components (the later comment) can't be lowered statically, so it's out of scope.
- Low real-world impact: this is the Tailwind v3 opacity pattern with a custom oklch palette, Tailwind v4 uses color-mix(), and oklch has been supported everywhere since 2023. Suggest `help wanted`. No reply needed.
