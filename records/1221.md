# #1221: `font-family: monospace, monospace` should not deduplicate (the duplication is load-bearing)

**bug / confirmed / high / action: queue-fix**

FontHandler dedupes font-family lists, so `monospace, monospace` becomes `monospace` (also in the `font` shorthand and with minify: false). A lone generic `monospace` makes browsers use the smaller default monospace size (13px vs 16px, and keyword-relative sizes like 1em/2em scale from 13px), while a two-item list doesn't. The dedupe must not reduce an all-`monospace` list to one entry.

**Evidence:** probe.mjs, Chrome 153, no author font-size: `font-family:monospace` => 13px; `monospace,monospace` => 16px; `monospace,serif` => 16px; `"monospace"` => 16px; `monospace;font-size:1em` => 13px; `monospace;font-size:2em` => 26px vs `monospace,monospace;font-size:2em` => 32px; <code>/<pre> default 13px. With an ancestor `font-size:16px` (absolute) all are 16px, so the effect only appears when the size derives from the initial/medium keyword. equivalence.mjs on the real normalize.css 8.0.1 (npm tarball) with --minify: NOT EQUIVALENT, code/pre font-size 16px -> 13px plus derived margins/heights. Gecko/WebKit not checked here (reporter and normalize.css docs say all three engines do it).

**Repro:** 1221-repro.mjs. `pre{font-family:monospace,monospace;font-size:1em}` -> `pre{font-family:monospace;font-size:1em}` on local, 1.33.0 ... 1.14.0. `code{font:1em monospace,monospace}` -> `code{font:1em monospace}`. Controls (Menlo,Menlo,monospace -> Menlo,monospace; monospace,monospace,serif -> monospace,serif) are correct.

**Fix:** In the dedupe, keep two entries when every entry is the generic `monospace` (dedupe otherwise). PR #1250 does exactly this with tests.

## Draft reply

Thanks, confirmed. In current Chromium a lone `font-family: monospace` still uses the smaller default monospace size (13px instead of 16px, and `2em` gives 26px instead of 32px), while `monospace, monospace` doesn't, so this isn't limited to old browsers. Lightning CSS reduces the list to a single `monospace` with or without `minify`, and in the `font` shorthand too. That changes real stylesheets: normalize.css 8.0.1 uses `font-family: monospace, monospace; font-size: 1em` for `pre`, `code`, `kbd` and `samp`, and after processing, code text renders at 13px instead of 16px.

There's an open PR, #1250, that keeps two entries when the list is only `monospace`. Until it lands, a workaround is to add a real font name before `monospace` or to set an absolute `font-size`.
