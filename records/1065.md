# #1065: Stylesheet visitor fails when using custom properties in 1.30.2

- **Type/status:** regression / confirmed
- **Severity:** high. **Action:** queue-fix. **Confidence:** high
- **Regression:** {'lastGood': '1.30.1', 'firstBad': '1.30.2', 'commit': '9879b91 Use serde-content instead of private serde types (#1062)'}
- **Related PRs:** #1357
- **Labels:** bug, area: custom visitors

## Summary
Since 1.30.2, any visitor that returns a node containing an Option field set to null fails to deserialize, e.g. `var()`'s `name.from: null` or `fallback: null`. The error is `expected an object-like struct named Specifier, found ()`. #1062 replaced serde's private Content with serde-content, whose deserialize_option treats Value::Unit (JS null) as Some(()). Serde's own Content treated Unit as None.

## Evidence
repro.mjs: wrong on local master, 1.33.0, 1.32.0, 1.31.1, 1.31.0, 1.30.2; correct on 1.29.0-1.30.1. Bisect: 1.30.1 -> 1.30.2. 9879b91 (#1062) is in v1.30.2 and not in v1.30.1. Read serde-content-0.1.2/src/de/mod.rs:355-369: only Value::Option(None) maps to visit_none, everything else to visit_some. The analysis by Brentlok in #1081 matches.

## Repro
1065-repro.mjs: `.foo { color: var(--color-red); }` with visitor `{StyleSheet(s){return s}}` -> `ERROR: failed to deserialize; expected an object-like struct named Specifier, found ()` (expected `.foo{color:var(--color-red)}`). 1065-repro-function.mjs: Function visitor returning `var(--a)` unchanged, same error. 1065-repro-nulls.mjs: same sheet with null fields stripped -> works, which confirms the null/Option root cause.

## Fix
small: Normalize Value::Unit to Value::Option(None) before deserializing buffered content (Property, CssRule, napi ValueOrVec), or patch serde-content. Open PR #1357 does the former with Rust and JS tests and says it fixes #1065 and #1081. Review and merge it rather than writing a new fix.

## Not verified
PR #1357 wasn't built or run (no Rust rebuild allowed). The WASM/playground build wasn't tested separately, though it shares the deserializer. Whether the Rust serde_json path (tests/test_serde.rs) also fails wasn't checked locally; PR #1357 says it does.

## Draft reply

Confirmed: this is a regression in 1.30.2 and still happens on 1.33.0. Returning a node that contains a `null` optional field, most commonly a plain `var()` (`from: null`, `fallback: null`), fails with `expected an object-like struct named Specifier, found ()`. It comes from #1062, which switched the internal deserializer to serde-content, and serde-content treats `null` as "present" for optional fields. 1.30.1 is the last good version.

Workaround until a fix is released: strip `null`-valued properties from the nodes you return, as shown in the comments here. Omitted fields deserialize fine. #1357 proposes a fix, and #1081 is the same issue.
