# #1399 A calculation that divides by zero is rejected, so `@media (min-width: calc(1px / 0))` is an error

**bug / confirmed / low / action: close**

Calc::parse_product only accepts `/` when the divisor folds to a non-zero number, so `calc(100px / 0)` and `calc(100px / (1 - 1))` fail to parse. Declarations fall back to unparsed tokens (output unchanged, still valid); `@media`/`@container` conditions fail with 'Invalid media query' in strict mode. css-values-4 says division by zero yields ±infinity, clamped at the top level; Chromium accepts it.

**Impact:** Agent-style spec report (batch #1391-#1406, same reporter), no real project or reactions. Nobody writes a literal division by zero: the idiom for an infinite value is `calc(infinity * 1px)`, which already works in declarations and media queries. In declarations the value is just kept as written (valid, unminified output). Only strict-mode media/container queries error; with errorRecovery the query is kept as written with a warning.

**Code:** src/values/calc.rs: Calc::parse_product, `/` arm (rejects a divisor that is not a non-zero Calc::Number with ParserError::InvalidValue)

**Repro:** triage/sweep/1399-repro.mjs. `@media (min-width: calc(1px / 0)) { .a { color: red } }` -> master, 1.33.0, 1.32.0, 1.31.1: `ERROR: Invalid media query` (errorRecovery: kept as written + warning). `.a{width:calc(100px / 0)}` -> kept unchanged. Control: `@media (min-width: calc(infinity * 1px))` -> `@media (width>=3.40282e38px)`.

Spec css-values-4 #calc-ieee: "Dividing a value by zero produces either +∞ or −∞, according to the standard sign rules" and "Infinities do not escape a top-level calculation; they're clamped".

**Fix (small):** In parse_product's `/` arm, fold x / 0 to x * f32::INFINITY (sign rules; 0/0 -> NaN) instead of erroring, and rely on the same top-level censoring that #1405 needs for NaN/infinity serialization. Best done together with #1405, not on its own.
