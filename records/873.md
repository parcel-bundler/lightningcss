## Draft reply

Thanks for the report and the follow-up example. Two notes: `dark only` is valid, since the `color-scheme` grammar (`[ light | dark | <custom-ident> ]+ && only?`) allows either order, and light-dark() follows `color-scheme` rather than `prefers-color-scheme`, so a media query alone wouldn't match native behavior.

The `.dark`/`.light` case is the same problem as #821: tokens defined on `:root` are resolved there, so a descendant changing `color-scheme` doesn't flip them. Let's track it there; there's an open PR, #1287, that addresses it for browsers with native light-dark() support. Meanwhile, `exclude: Features.LightDark` or targets of Chrome 123 / Safari 17.5 / Firefox 120 turn the transform off.

The toggles are emitted for every `color-scheme` even without light-dark() in the same file so that separately compiled stylesheets (e.g. a library and an app) work together.
