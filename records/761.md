## Draft reply

Thanks, confirmed on 1.33.0: `composes` in a plain class rule inside `@layer` (and `@media`/`@supports`) is rejected as if it were inside a nested style rule. The check currently treats any enclosing block as nesting. postcss-modules (used by css-loader and Vite) only rejects `composes` when a parent is a style rule and allows it inside at-rules, which seems like the right behavior here too, since `composes` only affects the exported class names.

Until it's fixed, the workaround is to put the `composes` in an unlayered rule for the same class and keep the styles in the layer:

```css
.foo { composes: bar from './other.module.css'; }
@layer components { .foo { /* styles */ } }
```
