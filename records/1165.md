# #1165 Scoped declarations

**feature + bug, confirmed, medium, queue-fix (implement, no flag).**

`@scope (.foo) { border: 1px solid black }` errors in strict mode. With errorRecovery it becomes `@scope(.foo){}`, silently dropping the declarations and any rules after them. The spec (css-cascade-6 Scoped Declarations) is settled, and @scope plus nested declarations ship in all engines; Chromium 153 applies it. Fix: allow declarations in the @scope body (`src/parser.rs`, AtRulePrelude::Scope) as NestedDeclarations, keeping source order. Related separate bug: lowering a nested `@scope` for chrome 118 drops the parent selector.

## Draft reply

Confirmed on 1.33.0: Lightning CSS doesn't yet accept declarations directly inside a top-level `@scope` (css-cascade-6 [Scoped Declarations](https://drafts.csswg.org/css-cascade-6/#scoped-declarations)). Strict mode errors. Worse, with `errorRecovery` the declarations are dropped, along with rules that follow them in the same block. This is valid, shipped CSS, so it should be supported without a flag. Until then, wrap them in a `:scope` rule:

```css
@scope (.foo) {
  :where(:scope) { border: 1px solid black; }
}
```

`:where()` keeps the zero specificity that scoped declarations have.
