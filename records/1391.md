# #1391: position with a CSS-wide keyword (unset/initial/inherit/revert) is emitted before an earlier position value

**bug / duplicate / medium / action: link-duplicate**

CSS-wide keywords on `position` are not parsed into the typed Position value; Property::parse falls back to Property::Unparsed, exactly like `position: var(--x)`. PositionHandler ignores Unparsed, so it is emitted immediately while the earlier parsed `position` is emitted at finalize, after it. This is the same root cause as #1225 (var()), just a different way to reach Property::Unparsed.

Duplicate of #1225 by root cause: CSS-wide keywords on `position` become `Property::Unparsed` (the same fallback as `var()`), and `PositionHandler` has no Unparsed arm. PR #1387 fixes it; ask for a CSS-wide-keyword test there. Browser-verified: computed `position` flips from static to absolute. Related to the property-order umbrella #572 only by symptom.

## Draft reply

Thanks for the clear report! This has the same cause as #1225: when a `position` value isn't a plain keyword like `absolute` (that includes `unset`/`initial`/`inherit`/`revert` as well as `var()`), Lightning CSS keeps it as raw tokens, and the `position` handler emits it right away while holding back the earlier value until the end of the block. That's why `.x{position:absolute;position:unset}` becomes `.x{position:unset;position:absolute}`. `direction` and `unicode-bidi` behave the same way.

There's an open PR, #1387, that addresses #1225 and should cover this case as well. Until then, `position: static` works as you found. Closing in favour of #1225 so the discussion stays in one place.
