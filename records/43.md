# #43 Comments are removed even with `minify: false`

**feature / feature-request / medium / needs-maintainer-decision**

Lightning CSS keeps `/*! ... */` comments only when they appear at the very start of a file (before any token), including per file in bundle(); all other comments are dropped because the tokenizer skips them. Arbitrary comment preservation conflicts with the typed-AST design and the maintainer previously declined it. Two narrow gaps remain in the existing feature: a license comment after `@charset` or after a UTF-8 BOM (both typical of Sass output) is dropped.

**Evidence:** repro.mjs on local (master c6a0c3c), 1.33.0, 1.32.0, 1.31.1: 4 controls correct, charset and BOM cases dropped on all. Also checked by hand: `/* @license */` (no !) dropped, `/*!` inside a declaration block dropped, `/*!` after the first rule or after @import dropped, with and without minify.

**Fix:** Small: in parse_with, also skip a leading BOM (open PR #1301 does this) and continue collecting `/*!` comments after an `@charset` rule. Larger option, if wanted: keep top-level `/*!`/`@license` comments between rules (esbuild legalComments style) as a new CssRule variant; this adds a union case to the JS AST (non-breaking) but must not block rule merging. Arbitrary comments everywhere is not compatible with the architecture.

**Open PRs:** #1301: Strips a leading UTF-8 BOM in parse_with and the bundler, with a test that `\uFEFF/*! license */` keeps the comment; fixes the BOM sub-case. Does not address the @charset sub-case.

## Draft reply

Status update: `/*! ... */` comments at the start of a file are preserved (since v1.21.1, also per file when bundling), with or without `minify`. Comments elsewhere are still dropped: the parser builds a typed AST and doesn't keep comments, so general comment preservation (e.g. `/*rtl:ignore*/` or Mailchimp's `@editable` markers) isn't supported. If you need those, run the tool that consumes them (e.g. rtlcss) before Lightning CSS.

We did find two cases where a leading license comment is dropped even though it should be kept: after `@charset "UTF-8";` and after a UTF-8 BOM, both of which Sass emits for files with non-ASCII characters. There's an open PR, #1301, that addresses the BOM case.

If your license comments sit between rules rather than at the top of a file, please share an example. That helps decide whether to support esbuild-style legal comments anywhere at the top level.
