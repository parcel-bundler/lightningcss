# #1072: `::scroll-button` "parsing error"

**Status:** duplicate of #1184 (Overflow 5 tracking; #1177 is the ::scroll-marker sibling) · **Severity:** low · **Action:** link-duplicate

- On master and 1.28.0+, `::scroll-button(right)` and `::scroll-button(*):disabled` pass through unchanged in strict mode, with a **warning**, not an error. Turbopack promotes warnings to errors, as devongovett noted. In 1.20 and earlier, strict mode errored on `::scroll-button(*):disabled`.
- Spec: css-overflow-5 ED defines `::scroll-button( '*' | <scroll-button-direction> )`. MDN: Chrome 135 only, experimental. Chromium 153 `CSS.supports` is true.
- Small side fix: the warning says "Did you mean ':scroll-button' (pseudo-class)?", which is misleading for a valid `::` pseudo-element (src/error.rs:280).
- Repro: `1072-repro.mjs`.

## Draft reply

Thanks for the report! The output is already right: since 1.28, Lightning CSS keeps `::scroll-button()` rules exactly as written and only emits a warning that it doesn't recognize the pseudo-element. The build failure comes from Turbopack treating that warning as an error, which we've raised with the Next.js team. Typed support for `::scroll-button()`, `::scroll-marker` and `::scroll-marker-group` (CSS Overflow 5, currently Chrome 135+ only) is tracked in #1184, so let's follow it there. Also, the warning's suggestion of a `:scroll-button` pseudo-class is misleading; your `::scroll-button` syntax is correct.
