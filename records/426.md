# #426 Individual Scale/Rotate/Translate properties being overwritten by Transform

**bug / fixed-on-master / high / action: keep-open**

Fixed by: PR #1340 (commit 40fb4ea, merged 2026-09-27, after v1.33.0; not yet released)

Up to 1.33.0, TransformHandler appended translate/rotate/scale declared after `transform` to its function list (in the wrong composition order) and dropped them when `transform` came later; `transform:none;translate:none` became `transform:translate(0,0)`. This breaks independent cascades and transitions and changes rendering. Master keeps each property as its own declaration.

**Impact:** Historically high: silently wrong output for a common pattern (translate:-50% -50% centering plus transform; scale transitions). 6 reactions, duplicate #1099, reports from Vite 8 and Next.js 16/Turbopack users. Every published release up to 1.33.0 is affected; severity stays high until the fix ships.

**Repro:** 426-repro.mjs. `.a{translate:-50% -50%;rotate:-45deg;transform:scale(98%) scaleX(-1)}` -> 1.33.0 `.a{transform:scale(.98)scaleX(-1)}`; master `.a{transform:scale(.98)scaleX(-1);translate:-50% -50%;rotate:-45deg}`. `.box{transform:translateY(-30px);scale:1.4}` -> 1.33.0 `transform:translateY(-30px)scale(1.4)` (wrong order); master unchanged.

**Evidence:** repro.mjs: all 5 bug cases WRONG on 1.33.0/1.32.0/1.31.1 and correct on local master; controls correct everywhere. equivalence.mjs (Chrome 153) on the four main patterns: master --minify output EQUIVALENT; 1.33.0 output NOT EQUIVALENT (2090 computed-style differences). Spec: css-transforms-2 individual transforms apply translate, rotate, scale, then transform.

**Fix:** Done in #1340. Close #426 when the next release ships it (or now, with a note that it lands in the next release).

**Not verified:** Old targets without individual-transform support (Chrome < 104, Safari < 14.1) now get the individual properties unchanged with no merged fallback; not evaluated whether that matters (those browsers are negligible today).

## Draft reply

Thanks for the report and the detailed follow-ups. This is fixed on master by #1340: `translate`, `rotate` and `scale` now stay separate declarations next to `transform` instead of being merged into it or dropped. For example, `.a{translate:-50% -50%;transform:translateY(.75rem)}` keeps both declarations, and `transform:translateY(-30px);scale:1.4` is no longer reordered. The fix is not in a published release yet (1.33.0 still has the bug), so it will ship in the next one. Until then, the workaround from the thread works: don't mix individual transform properties with `transform` in the same rule.
