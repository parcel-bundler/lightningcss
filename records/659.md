# #659 `@value` (import class names from other files): feature, needs maintainer decision (low)

- **Status:** a hard error in cssModules mode since 1.28.0 (#842, "The @value rule is deprecated"). With `errorRecovery` it is a warning and the rule is dropped. The maintainer declined value substitution in #6 (2021) and #865 (2024): "CSS variables are the successor to @value".
- **The new angle:** this issue's use case is importing another module's *hashed class name* into a selector (`.button .spinner`). CSS variables and `var(--x from "./file.css")` don't cover it, and there is no supported alternative. Demand: 11 reactions and 4 comments ("only blocker"). webpack and rspack support it.
- **Philosophy:** value substitution is out of scope: it's non-standard and needs raw-token substitution before every property is parsed. A narrow class-name-only import form could reuse the composes/`from` dependency machinery. That's a design decision.
- **Options:** (a) close as won't-fix, pointing to #865 and dashed idents; (b) accept only the class-name import form (`@value a from './x.css'` restricted to selectors) or another syntax for it.
- `659-repro.mjs` has controls only: the strict error, the recovery warning, and that the dashed-ident `from` alternative works.
