# #1163 Prebuilt binaries for ppc64le / s390x (and AIX)

**feature, feature-request, medium, action: needs-maintainer-decision**

Node.js core's doc build (Vite + lightningcss) fails on Node's own ppc64le and s390x CI machines because there is no `lightningcss-linux-ppc64-gnu` / `lightningcss-linux-s390x-gnu` package. Node disabled those CI jobs as a stopgap but says it must support them. Related: #1075 (s390x), PR #1217 (ppc64le + s390x), PR #1294 (s390x only). On #1294 you said this may not have wide enough usage and can't be tested. The new argument is that Node.js itself is the user.

- **PR #1217** is the one to review if you accept the platforms. Likely bug: `@napi-rs/cli` 2.18.4 has no `powerpc64le -> ppc64` mapping, so it emits `lightningcss.linux-powerpc64le-gnu.node`. `build-npm.js` (as patched) then looks for `lightningcss.linux-ppc64-gnu.node`, and the publish step would fail without a rename (IronBlood's fork does that rename). There's no on-hardware or QEMU test.
- **AIX:** not realistic (tier-3 Rust target). The WASM package is the fallback.
- **Repro** (`1163-repro.mjs`): checks that the two packages are in `optionalDependencies` (or, for master, in the triples in `build-npm.js`). Missing on master and in 1.31.1–1.33.0. The x64/arm64 control passes.

No draft reply: this needs your decision. If you accept: comment on #1217 about the ppc64le artifact name and suggest a QEMU smoke test. If you decline: reply pointing to `lightningcss-wasm` and building from source.
