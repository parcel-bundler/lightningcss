# #568 Remove System UI font stack

**feature/opinion, works-as-intended, low, needs-maintainer-decision (lean: keep, reply, close). Plus a real data bug found.**

The stack (from #182) is only injected for targets without `system-ui` support. With no targets or modern targets, the output is unchanged. The maintainer defended it in 2023 as a harmless fallback (same as postcss-preset-env).

**Finding:** browserslist `defaults` plus an outdated caniuse-lite db gives `android 131`, and compat.rs treats Android WebView < 150 as unsupported. Why: caniuse lists only the *current* WebView version, and `scripts/build-prefixes.js` takes the minimum 'y' version, so the threshold jumps to "latest" with every compat update. MDN says WebView 56.

Effects:
- Default-target users (e.g. Tailwind preflight) get the font stack.
- About 21 caniuse-sourced features are affected, including nesting and `:not()` list lowering.
- The output changed between 1.25.0 (correct) and 1.30.2 (wrong).

#1180/#1198 fixed only `#rrggbbaa` this way. Recommend a build-prefixes fix (use and_chr/MDN for android) or a new tracking issue.
