# #491 — More flexibility over cssModules pattern

**Type:** feature · **Status:** feature-request · **Severity:** low · **Action:** needs-maintainer-decision

Only `[name]`, `[local]`, `[hash]`, `[content-hash]` parse; `[hash:5]` / `[local:4]` give a clear "unknown placeholder" error (master and 1.31.1–1.33.0, `491-repro.mjs`). Request: webpack-style length suffixes or a JS function.

- A length suffix is small (Pattern::parse/write) and works in CLI/wasm/Rust; `[local:N]` can cause collisions, so refuse it or document it.
- PR #1262 (function pattern) is not ready. By reading the diff, synchronous `transform()` blocks the JS thread on `rx.recv()` while the call it waits for is queued to that same thread, so it likely deadlocks. It also un-gates threadsafe_function (risk to wasm/non-bundler builds), uses `content_hash` in the d.ts vs `contentHash` in the code, and has no tests. It changes the Rust `Pattern` API to an enum.
- PR #1237 covers only `[hash:N]` as part of a large webpack-parity change.

No draft reply; it needs a maintainer decision on direction (suffix vs function).
