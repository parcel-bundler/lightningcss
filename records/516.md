# #516 CSS Modules pattern crashes using [name]

**Status:** confirmed bug, still present on master and 1.33.0. **Severity:** medium. **Action:** queue-fix (small, good first issue).

`[name]` in `cssModules.pattern` with no `filename` (or a stemless one: `''`, `/`, `..`) panics at `src/css_modules.rs:161` (`path.file_stem().unwrap()`). Released builds use `panic = 'abort'`, so the Node process dies (exit 134) and try/catch cannot help. Passing `filename` works around it; it is required in `node/index.d.ts`, but plain JS users and the docs snippet (which elides it) are not warned.

Fix: replace the unwraps with a clear error ("[name] requires a filename") or an empty fallback; add tests in `src/lib.rs`.

Repros: `516-repro.mjs`, `516-repro-filename.mjs`, `516-repro-edge.mjs`.

## Draft reply

Thanks for the report, and sorry for the slow follow-up. This still happens on the latest release (1.33.0): with `[name]` in `cssModules.pattern` and no `filename` option, Lightning CSS panics, and in the published builds that aborts the Node process rather than throwing an error you can catch. The workaround is to pass `filename` to `transform()` (it is what `[name]` is derived from), e.g. `filename: 'src/logo.module.css'` gives `.my-company-logo-module-...-logo`. A missing filename should produce a clear error instead of a crash, so I'm leaving this open as a bug.
