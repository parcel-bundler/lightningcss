# #1402: calc(1 + 1px) accepted; sign(1em) folded

**bug · confirmed · medium (type-check part) / low (sign part) · queue-fix**

1. **No type check on +/-** (`Calc::add` / `parse_sum` in src/values/calc.rs). `calc(1 + 1px)` parses as a length. Chromium rejects it, as css-values-4 Type Checking requires. The reporter's example is contrived, but the same bug covers a **plausible typo, a missing unit**, and there it changes rendering (equivalence.mjs shows diffs):
   - `.a{width:100px;width:calc(100% - 20)}` → `.a{width:calc(100% - 20)}`. The valid fallback is dropped. This changed between 1.20.0 (correct) and 1.21.0.
   - `.a{margin:0 auto;margin-left:calc(50% - 10)}` → `.a{margin:0 auto 0 calc(50% - 10)}`. The browser drops the whole shorthand, so the centering is lost.
   - Strict mode also gives no error, so the developer never learns about the typo.
   - Same root cause: `hsl(from red calc(h + 1deg) s l)` → `#ff0400`. Chromium rejects it because the `h` channel keyword is a `<number>`. It was valid in older drafts, so tightening this needs a changelog note.
2. **sign() fold** (the `"sign"` arm of `Calc::parse_with`). `sign(1em)`, `sign(1rem)` and `sign(1vw)` fold to 1. That's wrong only when the reference size is 0 (Chromium: 0px / 5px at font-size:0). Fringe. Fix: fold only absolute lengths.

Fix: medium. Track a small "calc kind" at +/- and fail with InvalidValue on a mismatch. Strict mode then errors, and errorRecovery keeps the declaration unparsed, so it no longer takes part in dedupe or merging.

## Draft reply
Thanks, both confirmed on master and 1.31-1.33.

`calc()` sums aren't type-checked, so `calc(1 + 1px)` is treated as a valid length. Beyond the missing error, this matters for a common typo like a forgotten unit: `.a{width:100px;width:calc(100% - 20)}` minifies to just the invalid declaration, so the browser loses the `100px` fallback, and `margin:0 auto;margin-left:calc(50% - 10)` merges into a `margin` shorthand the browser drops. Per [CSS Values 4 type checking](https://drafts.csswg.org/css-values-4/#calc-type-checking) the sum is invalid, and Chromium rejects it.

The `sign(1em)` fold is also wrong in principle (it's 0 at `font-size: 0`), though that only matters in that edge case.
