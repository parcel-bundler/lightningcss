# #102 CSS modules with bundle()

**bug, confirmed, medium, needs-maintainer-decision.** With `bundle()` + `cssModules`, each file gets its own hash, but only the entry's classes are exported. Classes from imported files are renamed and unreachable, and the same class in two files gets two names. Unchanged in every release from 1.14.0 to 1.33.0. #1034 is the same symptom (closed by its reporter). Decide between a shared module scope for imports (the maintainer's 2022 comment) and per-file exports.

## Draft reply

Status update: on 1.33.0, `bundle()` with `cssModules` hashes each file separately, but only the entry file's classes appear in `exports`. With your example, `app.css`'s `.test` becomes a different name from `index.css`'s `.test`, and classes that exist only in `app.css` don't appear in the exports at all (same as #1034). That isn't what either of the options discussed above would produce, so this needs a decision on which model to support: imported files sharing the entry's module scope, or an export map per file. Until then, run `transform()` on each module file to get its own exports, and use `bundle()` with the same `cssModules` config only for the combined CSS. With the same filename (and `projectRoot`, if you set one), the class names match what `bundle()` writes.
