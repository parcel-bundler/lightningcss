# PR #1365: fix: keep transition and animation longhands after the shorthand they follow
**Verdict:** approve with nits. **Confidence:** high.

## Summary
`TransitionHandler`/`AnimationHandler` buffer the shorthand until finalize, but longhands they don't claim (untyped `transition-behavior`, `animation-trigger`; typed-but-unhandled `animation-composition`) are pushed to `decls` immediately, so they land *before* the buffered shorthand that resets them. The PR flushes the buffer before pushing such a longhand. The #1084 bug is real and confirmed in Chromium 153: `.a{transition:opacity 1s;transition-behavior:allow-discrete}` minifies on master to `.a{transition-behavior:allow-discrete;transition:opacity 1s}`, and computed `transition-behavior` goes `allow-discrete` -> `normal`. The PR fixes it in every config tested, with no regressions and no corpus size change. Built with `--on-master` (merged cleanly onto 574eee2).

## Design
- **Same pattern as #1209 (font), and they should share one helper.** #1209 adds a private `is_longhand_font_property(name)` in `font.rs` that is exactly `is_unknown_longhand(name, "font-")` from this PR (`properties/custom.rs`, `pub(crate)`). Whichever PR lands second should use the shared helper, and the arm is the same three lines in each (`Custom(val) if is_unknown_longhand(&val.name, P) => { self.flush(dest, context); dest.push(property.clone()) }`). #1209's extra `if self.has_any` guard is redundant (`flush` already returns early).
- **General rule.** The bug class is "a handler buffers a shorthand while a longhand that shorthand resets bypasses the buffer". I probed other buffered shorthands on master: `font`+`font-kerning`/`font-variant-numeric` (real, #1209). Reordered but harmless in Chrome because the shorthand does not reset them: `text-decoration-skip-ink`, `overflow-clip-margin`, `outline-offset`, `mask-type`, `background-blend-mode`, `margin-trim`. `text-wrap`, `white-space`, `mask-border-*`, `border-image-*`, `inset-*` kept order. So transition and font are the live instances; a per-handler prefix check via a shared helper is a reasonable granularity. A DeclarationHandler-level mechanism (each handler declares which unknown names its shorthand resets) would be more automatic but is not justified for two handlers.
- **Fully-parse philosophy.** Long term, `transition-behavior` should be a typed property and part of `TransitionHandler`'s shorthand (transitions-2 grammar includes `<transition-behavior-value>` in `<single-transition>`; today `transition: opacity 1s allow-discrete` passes through as unparsed). The prefix flush remains useful as a safety net for future unknown longhands, so not blocking.
- **animation-composition.** css-animations-2 says all `animation-*` properties "are all longhands of the 'animation' shorthand", so composition is a reset-only longhand per spec; animation-trigger is explicitly "a reset-only sub-property of the 'animation' shorthand" (animation-triggers-1). Chromium 153 does *not* reset `animation-composition` via `animation` (`.d{animation-composition:add;animation:fade 1s}` computes `add`) and doesn't support `animation-trigger`. So the animation half fixes nothing observable in Chrome today but follows the spec and costs nothing; keeping author order is the safe choice.
- Complexity: trivial, O(1) per declaration. No public API/AST change (`is_unknown_longhand` is `pub(crate)`).
- #1306 touches `AnimationHandler::flush` (timeline folding), not these arms; no conflict expected.

## Spec
- css-transitions-2 §2.6: "`<single-transition> = [ none | <single-transition-property> ] || <time> || <easing-function> || <time> || <transition-behavior-value>`" (https://drafts.csswg.org/css-transitions-2/#transition-shorthand-property) — transition-behavior is a longhand of `transition`, so the shorthand resets it.
- css-animations-2 §4: "These list-valued properties, which are all [=longhands=] of the 'animation' [=shorthand=]…" (https://drafts.csswg.org/css-animations-2/#animation-definition).
- animation-triggers-1: "'animation-trigger' is a [=reset-only sub-property=] of the 'animation' shorthand." (https://drafts.csswg.org/animation-triggers-1/#animation-trigger-shorthand)
- Chromium deviation: `animation` does not reset `animation-composition` (probe above).

## Findings
1. **nit: property-name matching is case-sensitive.** `.a{transition:opacity 1s;TRANSITION-BEHAVIOR:allow-discrete}` -> base and PR both `.a{TRANSITION-BEHAVIOR:allow-discrete;transition:opacity 1s}`; Chrome treats the name case-insensitively, so `transition-behavior` ends up `normal`. Unknown names keep their original case in `CustomPropertyName::Unknown`. Fix: compare the prefix with `eq_ignore_ascii_case` in `is_unknown_longhand` (e.g. `name.len() >= prefix.len() && name.as_bytes()[..prefix.len()].eq_ignore_ascii_case(prefix.as_bytes())`). #1209 has the same gap. Rare in practice.
2. **nit (size, acceptable):** flushing gives up a little dedup in rare patterns, e.g. `transition:opacity 1s;transition-behavior:allow-discrete;transition:color 2s` now keeps the dead first shorthand (base dropped it, also correctly). Zero change on every corpus file.
3. **nit:** the test comment in `test_animation` says "A longhand without a typed property" but `animation-composition` is typed.
