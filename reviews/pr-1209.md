# PR #1209: Preserve ordering of `font-*` properties that follow a `font` shorthand
**Verdict:** approve with nits. **Confidence:** high.

## Summary
`FontHandler` buffers `font` and its typed longhands until finalize, but untyped `font-*` longhands (parsed as `Property::Custom` with an `Unknown` name) are not claimed by any handler and are written out at once, landing *before* the shorthand, which then resets them (#1207). The PR adds a `Custom(val) if is_longhand_font_property(&val.name)` arm that flushes the buffer and then pushes the property. The bug is real: master 574eee2 `--minify` turns `p{font:12px serif;font-variant-numeric:oldstyle-nums}` into `p{font-variant-numeric:oldstyle-nums;font:12px serif}`, and Chromium computes `font-variant-numeric: normal` for it. Built merged onto master (574eee24) without conflicts.

## Design
- Same pattern as #1365 (transition/animation), which adds `pub(crate) fn is_unknown_longhand(name, prefix)` in `properties/custom.rs`. #1209's private `is_longhand_font_property(name)` is exactly `is_unknown_longhand(name, "font-")`. Whichever lands second should use the shared helper instead of its own copy.
- `if self.has_any { self.flush(..) }` is redundant: `FontHandler::flush` already returns early when `!self.has_any`.
- Both helpers compare names case-sensitively. `CustomPropertyName::Unknown` keeps the author's casing, and property names are ASCII case-insensitive, so `FONT-KERNING:none` after `font` is still reordered (Chromium applies `FONT-KERNING`). Pre-existing on master, not a regression; fix in the shared helper (ASCII case-insensitive prefix match) so both PRs benefit.
- The prefix rule is deliberately broad: it also flushes for `font-synthesis*`, which `font` does not reset (spec "Cascaded Independently" list). That costs nothing in correctness, only skips a reorder; corpus size is unchanged. Typed `font-palette` is not caught and doesn't need to be (not reset by `font`).
- Not covered: the `-webkit-font-feature-settings` alias (Chromium supports it, `font` resets it). Edge case, nit at most.
- PR's open question (Unparsed): known font properties with `var()` are `Unparsed` and already flush via the existing arm; unknown `font-*` with `var()` stay `Custom` and are covered (case "var in unknown" fixed). No extra arm needed.
- The general problem (a buffering shorthand handler lets unclaimed longhands jump ahead) exists in other handlers too (`list-style`, `border` with unknown sub-longhands reorder the same way), but those don't hit real resets in the cases I tried; #1365's helper is the reusable piece.

## Spec
css-fonts-4 `font` shorthand (Bikeshed source, raw.githubusercontent.com/w3c/csswg-drafts/main/css-fonts-4/Overview.bs): "Reset Implicitly ... and thus may not be set, but are reset to their initial values: font-feature-settings, font-kerning, font-language-override, font-optical-sizing, font-size-adjust, font-variant-alternates, font-variant-caps (css3 and above), font-variant-east-asian, font-variant-emoji, font-variant-ligatures, font-variant-numeric, font-variant-position, font-variation-settings". "Cascaded Independently ... font-palette, font-synthesis-weight, font-synthesis-style, font-synthesis-small-caps, font-synthesis-position."

## Findings
1. nit (pre-existing, incomplete): case-insensitive names not matched. `.foo{font:12px serif;FONT-KERNING:none}` -> base and PR `.foo{FONT-KERNING:none;font:12px serif}`; Chromium: kerning `auto` instead of `none`. Fix in the shared helper.
2. nit: duplicate of #1365's `is_unknown_longhand`; share whichever lands second.
3. nit: redundant `if self.has_any`.
4. nit: `-webkit-font-feature-settings` after `font` still reordered (still-broken in Chromium check).

## Edge cases checked
28 cases x 2 configs (`--minify`, `--minify --targets 'chrome 80'`): 30 fixed, 12 ok, 6 still-broken, 8 changed, 0 regressions.
| case | result |
|---|---|
| issue/PR examples, feature/variation-settings, size-adjust, optical-sizing, ligatures, east-asian, `font-variant` shorthand, `font-variant-caps` then `font-variant`, full longhands combining into `font` then kerning, var() in longhand, nesting, system-ui lowering, `color` in between | fixed |
| uppercase / mixed-case name, `-webkit-font-feature-settings` | still-broken |
| `font-family:serif;font-size:12px;font-kerning:none;font-weight:bold`; `font;kerning;font`; `line-height:2;font-kerning:none;line-height:3`; `font-synthesis` | changed, equiv (order kept; dead earlier decl now kept, a few bytes) |
| `!important` on either, `--font-kerning`, `font-palette`, var() in `font`, kerning before font | ok |
