# PR #1039: Add selector name to PURE error message
**Verdict:** request changes (small; author is a team member, draft). **Confidence:** high.

## Summary
Changes `MinifyErrorKind::ImpureCSSModuleSelector` from a unit variant to `{ selector: String }` and the message to
`Selector "<sel>" is not pure. Pure selectors must contain at least one local class or id.` (same wording as css-loader /
postcss-modules-local-by-default). Useful: today the error only carries the rule's start location, so with a long selector
list the user has to guess which part failed. Merges cleanly onto current master (574eee24); `test_selectors` passes. No CI runs on the draft.

## Design
- The selector string is the whole `SelectorList` (`self.selectors.to_string()`, `scope_start/end.to_string()`), not the
  selector that failed. The check is already `.all(is_pure_css_modules_selector)`, so `.find(|s| !is_pure_css_modules_selector(s))`
  and `to_css_string` on that `Selector` gives the precise one at no extra cost. Prototyped for style rules
  (scratchpad/pr1039-first-impure.diff, 4 lines); same change applies to both branches in `rules/scope.rs`.
- `:global()` / `:local()` are stripped by the normal serializer (`PseudoClass::Global` serializes its inner selector,
  selector.rs ~838), so the message shows `.foo` for `:global(.foo)`, which contradicts "must contain a local class".
  Fixing this needs either a crate-private printer flag that keeps the `:global()`/`:local()` wrappers when serializing for
  diagnostics, or not echoing global parts. Maintainer call on how much machinery is worth it; at minimum report only the impure selector.
- Serialization is the minified/normalized form (`::before` -> `:before`, `[foo=bar]` -> `[foo="bar"]`), not source text. Acceptable.
- Only runs on the error path, so no perf concern.

## API impact
- **Rust: breaking.** Public enum variant changes from unit to struct; any `match`/construct of
  `MinifyErrorKind::ImpureCSSModuleSelector` stops compiling. Crate is 1.0.0-alpha.72, so it can ship in an alpha bump but needs a changelog note. Consistent with sibling variants (`CircularCustomMedia { name }`).
- **JS/serde:** `#[serde(tag = "type")]`, so `data` goes from `{"type":"ImpureCSSModuleSelector"}` to
  `{"type":"ImpureCSSModuleSelector","selector":"..."}`: additive. No `.d.ts` mention of this error. Message text changes (anyone string-matching the old text breaks; unlikely).

## Findings
1. **Should fix: whole selector list reported.** Input `.a, :global(.foo), .b {width:20px}` (pure mode) -> PR: `Selector ".a, .foo, .b" is not pure`. A 60-class list plus `div` prints all 61 selectors. With first-impure prototype: `Selector ".foo"` / `Selector "div"`.
2. **Should fix / maintainer decision: `:global()` dropped.** `:global(.foo) {}` -> `Selector ".foo" is not pure...local class`; `a:not(:global(.x))` -> `a[href="x"]:not(.x)`; `@scope (.a) to (div, :global(.x))` -> `"div, .x"`. Misleading because the shown selector looks like it contains a class. The PR's own test enshrines `".foo"` for `:global(.foo)`.
3. **Note: Rust public API break** (above); call it out in the changelog.
4. Pre-existing, out of scope: `is_pure_css_modules_selector` treats `:not(.x)` as pure, so `:not(.x) {}` passes pure mode though it matches almost everything. Not changed by this PR.

## Edge cases checked (temporary probe test in PR worktree, reverted)
| input (pure mode) | PR message selector | first-impure prototype |
|---|---|---|
| `:global(.foo)` | `.foo` | `.foo` |
| `.a, :global(.foo), .b` | `.a, .foo, .b` | `.foo` |
| `:global(.foo) div` | `.foo div` | `.foo div` |
| `:local(div)` | `div` | `div` |
| `div, .foo` | `div, .foo` | `div` |
| `html { .foo { span {} } }` | `html` | `html` |
| `@media(...) { div:hover::before {} }` | `div:hover:before` (loc 0:27, correct) | same |
| `@scope (.a) to (div, :global(.x))` | `div, .x` | (scope not prototyped) |
| 60 classes + `div` | all 61 | `div` |
JSON for serde: `{"type":"ImpureCSSModuleSelector","selector":".foo"}`.
