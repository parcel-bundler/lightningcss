# PR #1374: Preserve parsed declarations during error recovery
**Verdict:** approve. **Confidence:** high.

## Summary
Removes the two `declarations.clear()` / `important_declarations.clear()` calls in `NestedRuleParser::parse_nested` (src/parser.rs) that ran whenever any item in a declaration-accepting block failed to parse. With `errorRecovery`, every declaration parsed *before* an invalid item (disallowed nested at-rule such as `@keyframes`/`@font-face`, `*zoom:1` hack, invalid nested selector, bad `!important`) was silently dropped. Bug is real and long-standing (#1358): base `.a{color:red;width:1px;@keyframes k{from{opacity:0}}height:2px}` → `.a{height:2px}`; PR → `.a{color:red;width:1px;height:2px}`. Strict mode still errors (unchanged; errors are collected and the first is returned).

## Design
- The clear was purely destructive: `parse_declaration` (src/declaration.rs) pushes into the list only after the whole declaration, including `!important` and `expect_exhausted`, succeeded, so there is never a partially-pushed declaration to roll back. Nested rules push to `rules` only on success, and the clear never touched them anyway (which is why declarations after a nested rule already survived on base: `.a{color:red;& b{..}width:3px;@keyframes k{}height:4px}` lost only `color:red`).
- The fix makes `parse_nested` consistent with `DeclarationBlock::parse` (style attributes / `PropertyDeclarationParser`), which already warns and continues without clearing.
- Minimal and in the right place; no other copies of the pattern exist (`grep clear()` in parser/declaration/rules). No API/AST change. Fits the error-recovery policy: drop exactly the invalid item, keep neighbors as a browser does (pitfalls §6).
- Small leftover: the `errors` Vec + deferred warning is now only needed for strict mode's "return first error"; it could warn immediately in recovery mode, but behavior is the same. Not worth requesting.

## Spec
CSS Syntax 3, "consume a block's contents" (https://drafts.csswg.org/css-syntax-3/#consume-block-contents): for an at-keyword, "If |decls| is not empty, append it to |rules| … Consume an at-rule … If a rule was returned, append it to |rules|"; for a failed declaration, "restore a mark … consume a qualified rule … If an invalid rule error was returned: If |decls| is not empty, append |decls| to |rules|". Earlier declarations are never discarded. (Spec splits them into a following CSSNestedDeclarations list; merging into one block, as the PR's output does, is cascade-equivalent since nested declarations use the parent's specificity and order is preserved.)
Chromium 153 CSSOM: `.a{color:red;width:1px;@keyframes k{from{opacity:0}}height:2px}` → `.a { color: red; width: 1px; height: 2px; }`; `.b{color:red;*zoom:1;width:1px}` → `.b { color: red; width: 1px; }`; `.c{color:red; & > > b{color:blue} width:3px}` → `.c { color: red; width: 3px; }`.

## Findings
None blocking.
1. nit: the Node test asserts the warning location `column: 36`, which points into the `@keyframes` prelude/block rather than at `@` (column 24). Pre-existing location behavior, but the test now pins it. Optional.
2. Out of scope (pre-existing, not changed by PR): declarations directly inside `@scope` (`@scope (.a){color:red;width:1px}`) are rejected/dropped on both base and PR (`@scope(.a){}`), parsed as selectors. Possibly worth a separate issue.

## Edge cases checked
25 cases × 3 configs (`--minify --error-recovery`; `--error-recovery --targets 'chrome 90'`; `--minify --error-recovery --targets 'safari 12' --targets 'chrome 90'`): 54 fixed, 18 ok, 3 changed, 0 regressions.

| case | result |
|---|---|
| issue keyframes / font-face / `*zoom` / bad `!imp` / invalid nested selector | fixed (base drops earlier decls) |
| important before error, multiple errors, following rule, `@layer` wrapper | fixed |
| shorthand before error (`margin:1px;@keyframes k{}margin-left:5px` → `margin:1px 1px 1px 5px`) | fixed; shorthand merge across error correct |
| custom property / `var()` before error, prefixed property with targets | fixed |
| error inside nested `@media`/`@supports`/nested style rule | fixed |
| error after/before nested `& b{}` rule (HTML fixture) | fixed |
| `@starting-style` body with error | changed (now keeps `opacity:0`; base not observably different in oracle), correct |
| duplicate property across error, longhand-then-shorthand, `!important` override across error | ok (unchanged) |
| neighbors without errors, top-level `@media` with invalid child, `@scope` body | ok (unchanged) |

Strict mode: CLI still errors on the issue input.
