# PR #909: Add failing test for composing default class
**Verdict:** approve with nits (needs a one-line rebase fix to the test). **Confidence:** high.

## Summary
Fixes #908. `composes` class names were parsed with `CustomIdent::parse`, which rejects `initial`, `inherit`, `unset`, `default`, `revert` and `revert-layer`. The `Composes` parse then failed and `Property::parse` fell back to `Property::Unparsed`, so `composes: default` was silently dropped from the exports and leaked into the CSS output as a literal `composes: default;`. Despite its title, the PR contains the fix: `parse_one_ident` now builds `CustomIdent(input.expect_ident()?)`, still rejecting `from`. The bug is real: base `.default{color:blue}.foo{composes:default;color:red}` -> `foo.composes: []`, and the CSS keeps `composes: default;`.

## Design
- **Keyword side effect.** CSS-wide keywords (`inherit`, `INHERIT`, `revert-layer`, …) now also become class references, both local and `from "file"`/`from global`. That is the right behavior:
  - `composes` is not a real CSS property, it never reaches a browser, and its operands are class names, not `<custom-ident>`s. Every one of these is a valid class name (`.inherit{}` parses and is exported today).
  - postcss-modules 6.0.1 (postcss-modules-scope 3.2.1, also used by css-loader and Vite) splits the value on whitespace and treats every word as a class name with no keyword filtering. Verified: `.inherit{color:blue}.foo{composes:inherit}` -> `{"inherit":"inherit_x","foo":"foo_x inherit_x"}`, and the same for `default`, `unset` and uppercase `INHERIT`. The PR matches that.
  - On master, `composes: inherit` did not mean "inherit" either. It became an unparsed declaration, was printed into the output, and was dropped from the exports. No meaningful behavior is lost.
- **Placement.** The fix is local to `parse_one_ident`, which is the only place that parses composes names. `src/selector.rs:1133` already builds `CustomIdent(id.into())` for class names the same way, so there is precedent. Switching the field to `Ident` would change the AST/serde type (a breaking change) for no benefit. No API or AST change.
- **Philosophy.** The values are fully parsed and the change is not non-standard. It only widens what is accepted for a CSS-modules-only property.

## Spec
There is no CSSWG spec. The css-modules README describes `composes: className [className…] [from "file" | global]`, with operands that are class names; it has no reserved-word rule. The reference implementation (postcss-modules-scope) is quoted in its behavior above.

## Findings
1. **Should fix (rebase).** The new test no longer compiles on current master. `css_modules_test` now takes `CssModuleReferences = IndexMap`, and the test passes `HashMap::new()` (error E0308 at `src/lib.rs:27348` after merging onto 574eee2). Change it to `IndexMap::new()`. With that change, `cargo test --lib css_modules` passes (2 passed).
2. **Nit.** The PR title says "Add failing test", but the PR includes the fix. It could be retitled, and could add a case for a CSS-wide keyword (e.g. `composes: inherit`) to pin down the intended behavior.
3. **Pre-existing, not in this PR.**
   - Unparseable `composes` values (`composes: 1a`, `composes: from`, `composes: a from`) still fall back silently to an unparsed declaration that leaks into the output, with no error even in strict mode. That is arguably worth a `ParserError` for a known property, but it is a separate issue.
   - The minified output keeps a trailing `;` where `composes` was removed: `._x_foo{color:red;}`. This also happens on master for any `composes`.

## Edge cases checked (CLI, `--css-modules`; base = master 574eee2, PR merged onto it)
| case | base | PR |
|---|---|---|
| `composes: default` | `[]` + leaked decl | local ref, decl removed (fixed) |
| `composes: inherit` / `INHERIT` / `revert-layer` | `[]` + leaked | local ref (matches postcss-modules) |
| `composes: a default unset b` | all 4 lost, leaked | all 4 refs in order |
| `composes: default inherit from "./x.css"` | lost | 2 dependency refs |
| `composes: initial from global` | lost | global ref |
| `composes: from` / `a from` / `1a` | leaked | unchanged (leaked) |
| `--minify`, `--error-recovery` | as above | as above |

No browser equivalence check: `composes` never reaches the browser, and the only CSS output change is removing the leaked invalid declaration.
