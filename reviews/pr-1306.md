# PR #1306: Fix animation-timeline being folded into the animation shorthand
**Verdict:** approve with nits. **Confidence:** high.

## Summary
Lightning CSS folds `animation-timeline` into the `animation` shorthand (`animation:1ms linear both parallax view()`), which every engine rejects, so the whole animation is dropped (#1283; dups #1342, #1369; sub-case of #572). The PR (1) filters BCD `partial_implementation` out of `animationTimelineShorthand` in `scripts/build-prefixes.js` and regenerates `src/compat.rs`, so the feature is now `return false` for all browsers, and (2) in `AnimationHandler::flush` only folds the timeline when targets are *set* and support it, so the no-targets case (where `Targets::is_compatible` returns true) is fixed too. The bug is real: Chromium 153 `CSS.supports('animation','foo 1s view()')`, `scroll()` and `--t` are all `false`; `CSS.supports('animation-timeline','view()')` is `true`. Base output for the issue input with no targets and with `chrome 115` is the dropped shorthand; PR output is `animation:1ms linear both parallax;animation-timeline:view();animation-range:exit`.

## Design
- **Follows the maintainer's earlier request** (comment 2026-09-27: "just fix the AnimationTimelineShorthand compat data (partial support should not imply full support)"). The `Animation` struct and parser are untouched; no public API/AST change.
- **General rule?** I checked whether the partial filter should go into the shared `for (let feature in mdnFeatures)` loop for all features. It should not: with BCD 8.0.7 that would flip `mediaRangeSyntax` (Firefox 63+), `colorFunction` (Safari 10.1+), `imageSet` (all browsers), `fontStyleObliqueAngle`, `highlight` — all intentionally treated as supported today. Per-feature filtering is the right granularity. Nit: the same `Object.fromEntries(...map(partial filter))` block is now copy-pasted three times (`mediaIntervalSyntax`, `statePseudoClass`, this one); a small `withoutPartial(support)` helper would be tidier. The PR uses `{version_added:false}` instead of `undefined` because Chrome's entry is a single object (the generic loop would crash on `undefined.alternative_name`) — correct, and arguably the helper should do that for all three.
- **No-targets special case** (`context.targets.browsers.map_or(true, |b| !Feature::AnimationTimelineShorthand.is_compatible(b))`): this departs from the usual "no targets = assume support" convention, but for a feature no engine implements, that convention produces CSS broken everywhere (#1369 is exactly this report). Precedent exists for `browsers.is_some()` checks (flex.rs, display.rs, background.rs). Folding is an optimization, so making it opt-in is the conservative choice per CLAUDE.md ("When unsure whether a transform preserves meaning, it must not be applied"). Since compat now returns false everywhere, the fold is effectively dead code until browsers ship; that is fine and keeps the struct as the maintainer wanted. Worth the maintainer's explicit sign-off because it goes slightly beyond his comment.
- No new loops, allocations or complexity; perf unaffected.

## Spec
css-animations-2 ED §4.12 (https://drafts.csswg.org/css-animations-2/#animation-shorthand), fetched today:
> `<single-animation> = <'animation-duration'> || <easing-function> || <'animation-delay-start'> || <single-animation-iteration-count> || <single-animation-direction> || <single-animation-fill-mode> || <single-animation-play-state> || [ none | <keyframes-name> ] || <single-animation-timeline>`

So per spec the timeline *is* settable through the shorthand; Chromium implements it reset-only (BCD note: "Support is currently reset-only. Including `animation` resets a previously-declared `animation-timeline` value to `auto`, but `animation-timeline` cannot be set via `animation`"). BCD 8.0.7 (PR lock) and 8.1.10 (current master data) both mark Chrome/Edge/Opera/Samsung/WebView partial and Firefox/Safari `false`. scroll-animations-1 makes `animation-range-*` reset-only sub-properties of `animation`; the handler already emits range after the shorthand.

## Findings
1. **should fix (mechanical): conflicts with master.** `git merge-tree origin/master refs/review/pr-1306` conflicts in `scripts/build-prefixes.js` (adjacent `accentSystemColor` change from #1420). `src/compat.rs` auto-merges; master's BCD 8.1.10 still marks the entry partial, so regenerating after rebase gives the same `return false`. Ask for a rebase + regenerate.
2. **nit:** factor the three partial-filter copies into a helper (see Design).
3. **note (pre-existing, not this PR):** input written with a timeline in the shorthand (`animation:p 3s view(inline 10px)`) is spec-valid but dropped by Chromium; the PR now rewrites it as `animation:3s p;animation-timeline:view(inline 10px)`, which works. That is output following the spec rather than browser bugs, consistent with the philosophy; cases.mjs flags these as "regression" only because the oracle compares against the (Chrome-dropped) input. Similarly `animation:b 2s;animation:p 1s view()` drops the first (Chrome-valid) declaration on both builds — pre-existing dedup-of-fallback behavior for spec-valid values.
4. **side benefit:** `animation:p 1s;animation-timeline:none` was folded into `animation:1s p none` on base (ambiguous with `none` keyframes name; Chrome drops it); PR keeps the longhand.
