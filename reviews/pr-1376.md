# PR #1376: Carry forward missing components in color-mix()
**Verdict:** approve with nits. **Confidence:** high (behavior), medium (API-policy call).

Author: ybai08. Fixes #1368. +157/-0 in `src/values/color.rs`, `src/lib.rs`. Built with `build-pr.sh --on-master 1376` (merged cleanly onto master 574eee24). No CI check runs on the head commit yet (fork PR awaiting approval).

## Summary
`CssColor::interpolate` converts each color into the interpolation space before `fill_missing_components`, and the conversions resolve `none` to 0, so cross-space `none` was never carried forward. The PR records which components are missing in the original color, maps them to the interpolation space with css-color-4's analogous-component table plus the "analogous set" rule, and re-sets them to NaN after the powerless adjustment and before the fill. The bug is real: master gives `color-mix(in hsl, lch(none none 180), hsl(11 33 44))` → `#4b2d26`; WPT and Chromium expect `#95594b`, which is what the PR gives.

## Design
- Fix is in the right place: one spot in the generic `CssColor::interpolate`, applies to every interpolation space and every source color type (LAB/LCH/OKLAB/OKLCH, all predefined RGB + XYZ, rgb/hsl/hwb). `RGBA` (u8, no `none`) and LightDark (handled recursively before) are covered correctly.
- The category table keys off `ColorSpace::channels()` name tuples (`("r","g","b")`, `("l","a","b")`, …). Works for every defined space (I checked all `define_colorspace!` structs), but it's string-matching; a slightly more robust alternative is to emit the categories from `define_colorspace!`. Not worth blocking.
- Cost: only runs inside color-mix resolution, constant work per mix. No hot-path impact; size-check shows zero change.
- **API (should fix, cheap):** adds a required method `set_missing_components` to the public `pub trait Interpolate` (`lightningcss::values::color::Interpolate`), which breaks any external implementor, and adds a `ColorSpace` bound to the public generic `CssColor::interpolate<T>`. External implementors are very unlikely (the trait is plumbing for color-mix), but per CLAUDE.md it should be avoided or called out. Suggest a default no-op body (`fn set_missing_components(&mut self, _missing: [bool; 4]) {}`), with the macro overriding it. The `ColorSpace` bound only affects callers passing a custom `T`, which must already satisfy ~8 crate traits; acceptable but worth a mention in the changelog.
- Philosophy: spec feature from css-color-4 (CR), not a draft; no flags needed.

## Spec
css-color-4 §13.3 Interpolating with Missing Components (Bikeshed source, csswg-drafts main, fetched 2026-11-23):
> "If any [=analogous components=] which are [=missing components=] are found, they will be **carried forward** and re-inserted in the converted color before premultiplication, and before linear interpolation takes place."
> "Similarly, if every component of an [=analogous set=] (defined below) in the original color is a [=missing component=], they are all [=carried forward=] and re-inserted in the corresponding [=analogous set=] of the [=interpolation color space=]."
> "Additionally, for any two color spaces, the components that remain after removing all [=analogous components=] form an [=analogous set=] of components."
Table: Reds r,x; Greens g,y; Blues b,z; Lightness L; Colorfulness C,S; Hue H; Opponent a; Opponent b; Alpha. "The Whiteness and Blackness components of HWB have no analogs."
https://drafts.csswg.org/css-color-4/#interpolation-missing — the PR's table and analogous-set logic match this text exactly, including the spec's own examples (`lab(50% none none)`→`lch(50% none none)`, `rgb(none none none / 50%)`→`oklab(none none none / 50%)`).

**Browser deviation:** Chromium 153 does not implement the analogous-set rule (`color-mix(in lch, lab(50 none none), lch(11 33 44))` → Chromium `lch(30.5 16.5 44)`, WPT expects `lch(30.5 33 44)`, PR gives the WPT value) and resolves `none` inside legacy `rgb()/hsl()/hwb()` to 0 at parse time (`hwb(180 none none)` serializes as `rgb(0, 255, 255)`), while WPT `color-computed-none.html` expects those `none`s to carry forward. So Chromium is not the oracle here; WPT expectations are.

## Findings
1. **should fix (API):** required trait method added to public `Interpolate`; give it a default body. Optionally note the new `ColorSpace` bound.
2. **nit:** channel-name string matching for categories; could be generated by `define_colorspace!`.
3. **pre-existing, not this PR (follow-ups the author already listed):** converted inputs are gamut-mapped before mixing (spec: "These are not clipped; the values must be interpolated as-is"), so e.g. `color(xyz none 0.5 1)` in srgb still fails; `adjust_powerless_lch!/lab!` treat chroma/a/b as powerless at L=0; achromatic detection with `f32::EPSILON`. Also observed: `color-mix(in hsl longer hue, hsl(none 50% 50%), hsl(30 50% 50%))` gives hue 30 on master too while Chromium gives 210 (equal-hue `longer` handling) — unrelated to this PR.

No regressions against WPT expectations found.
