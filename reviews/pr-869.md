# PR #869: feat(playground): add option to switch between parsers
**Verdict:** request changes (small, easy fixes). **Confidence:** high.

## Summary
Website-only (+15/-2 in `website/playground/{index.html,playground.js}`): adds a "Parser" select (style sheet / style attribute) and calls the wasm `transformStyleAttribute` when "style-attribute" is chosen. No Rust, API or generated-file changes. Merges cleanly onto current master (`git merge-tree` clean; master's playground last touched 22bdda3d, unrelated). Feature works, but shared links don't restore the parser choice, and the CSS-modules pane goes stale in attribute mode.

## Design
Fine and minimal. `transformStyleAttribute` (wasm/index.mjs, napi `AttrConfig`) takes filename/code/targets/include/exclude/minify/analyzeDependencies/errorRecovery and a visitor; `AttrConfig` has no `deny_unknown_fields`, so the extra `cssModules`/`drafts`/`unusedSymbols` the playground passes are ignored, not errors. `AttrResult` has no `exports`.

## Findings
1. **should fix — parser not restored from shared link.** `parser` is written into the URL hash by `savePlaygroundState`, but `reflectPlaygroundState` never reads it. Loading `#{"source":"color: red; background: yellow","parser":"style-attribute",...}` in Chromium: select shows `style-sheet`, output `/* ERROR: Unexpected end of input */`, and the first `update()` rewrites the hash with `parser: "style-sheet"`, so the shared state is lost. Fix: `if (playgroundState.parser) parser.value = playgroundState.parser;` in `reflectPlaygroundState`. Verified: with that line the same link shows `style-attribute` and output `color: red; background: #ff0`.
2. **should fix (minor) — stale CSS-modules pane.** With CSS modules checked, after switching to style-attribute the modules pane stays visible and keeps the previous stylesheet's exports (`"foo": {"name": "EgL3uq_foo", ...}`), because `update()` only writes the pane when `res.exports` is truthy. Fix: clear the pane when there are no exports (or hide it / disable the CSS modules checkbox in attribute mode). Verified clearing works.
3. **nit** — `<select id="parser" value="style-sheet">`: `value` isn't a `<select>` attribute; the first option is the default anyway. Labels "Style-Sheet"/"Style-Attribute" could be "Style sheet"/"Style attribute".
4. **nit** — Default source is a stylesheet, so switching parser on the default state shows an error. Acceptable for a debugging tool.

## Edge cases checked
| case | result |
|---|---|
| select style-attribute (form `input` event) | re-runs transform, hash gets `parser` |
| shared link with parser=style-attribute | **not restored** (finding 1); fixed by 1-line patch |
| attribute mode + analyzeDependencies (`background:url(b.png)`) | works, url placeholder in output |
| attribute mode + CSS modules | stale exports pane (finding 2) |
| extra options (drafts, unusedSymbols, cssModules) to transformStyleAttribute | ignored, no error |
| visitor in attribute mode | supported by napi `compile_attr` (code read, not run) |
