## Summary
Logical-property (`ltr`/`rtl`), `@supports` and dark-mode fallbacks collected while minifying a
`NestedDeclarationsRule` go into the child `PropertyHandlerContext` that `StyleRule::minify` creates for nested
rules, and that context is thrown away, so `.btn1{:where(&){…} border-start-start-radius:…}` loses the radius
with targets (#1049, real: confirmed on master, browser-checked with an explicit RTL/LTR fixture). The PR merges
the child context back into the parent so the parent's `CssRuleList::minify` emits the fallbacks with the
parent selector.

It fixes #1049 and the scenario of draft #1061, but it is the wrong place: *every* fallback created anywhere in the
nested rule list (including inside `@media`, `@supports`, `@container`, `@layer` blocks) is hoisted to the parent
and emitted unconditionally, and parent + nested values for the same property are merged into one rule where the
later (conditional) one wins. This produces new wrong output on screen for inputs that base handled correctly (or
only got wrong in the condition). It does **not** fix #1246.

## Design
- The bug is "fallbacks from a nested declarations rule are never drained". The reusable fix is to drain them
  where the nested declarations rule is minified, in `CssRuleList::minify`'s `CssRule::NestedDeclarations` arm,
  and emit them right there in the child list (same position, same conditional wrapper). PR #1386 already does
  exactly that for `@supports` (`take_nested_supports_rules`, emits `@supports{ NestedDeclarations }` after the
  rule); it should be extended to `ltr`/`rtl` (nested style rules with `&:not(:lang(…))`/`&:lang(…)` or
  `&:dir()` selectors via `get_additional_rules` on a `&` selector) and `dark`. That fixes #1049, #1246 (the next
  sibling no longer steals the leftovers) and keeps `@media`/`@container`/`@layer` conditions and source order.
- Merging contexts loses the boundaries between distinct declaration blocks: `ltr`/`rtl` are flat lists, so the
  parent's and the nested blocks' values end up in one generated rule and dedup keeps the last.
- No perf concern (Vec::extend), no size change on the corpus.

## Spec
css-nesting-1 nested declarations rule: declarations after a nested rule are wrapped in a nested declarations rule
"with the same specificity behavior as the parent style rule", appearing in place in the child list. Conditional
group rules nested in a style rule apply only under their condition. (Not freshly quoted from the ED in this
session; the findings below don't depend on fine spec wording, they are browser-verified.)

## Findings
1. **Blocking: fallbacks escape conditional group rules.** Logical declarations inside a nested `@media`,
   `@supports`, `@container` or `@layer` are hoisted to the parent and emitted unconditionally.
   - `.foo{color:red;@supports (display:nope){border-start-start-radius:10px}}` (chrome 80) — base:
     `.foo{color:red}@supports (display:nope){}` (equivalent); PR: `.foo:not(:lang(…)){border-top-left-radius:10px}…`
     outside @supports → radius applies always. Browser: regression (same for `@container (min-width:5000px)`).
   - `.foo{border-top-left-radius:3px;@layer x{border-start-start-radius:10px}}` — layered value now emitted
     unlayered and beats the unlayered 3px. Browser: regression.
   - `.foo{color:red;@media (max-width:100px){border-start-start-radius:10px}}` — radius applies at every
     width (base dropped it; both wrong but PR now wrong on screen everywhere).
2. **Blocking: parent value overwritten by a conditional nested value.**
   `.foo{border-start-start-radius:4px;@media print{border-start-start-radius:20px}}` (safari 14) —
   base: `.foo:not(:lang(…)){border-top-left-radius:4px}…@media print{}`; PR:
   `.foo:not(:lang(…)){border-top-left-radius:20px}…@media print{}`. On screen the element gets 20px instead of
   4px. Same with the #1023 shape `h1{margin-inline-start:1px;@media (width<10px){margin-inline-start:2px}}`
   (chrome 68): base `margin-left:1px`, PR `margin-left:2px` unconditionally. Both browser-confirmed.
3. **Should fix: #1246 not fixed.** `.btn{&:focus{…} border-start-start-radius:8px; &:hover{…}}` and the issue's
   `@media … ; border-start-start-radius; &:hover` input produce identical output on base and PR: the radius is
   still attached to `.btn:hover` only, because the next sibling style rule drains the child context before the
   PR merges it back.
4. **Nit: the new test enshrines blank output.** The `prefix_test` expectation ends in `\n\n\n` from the now-empty
   nested declarations rule (pre-existing printing artefact, also on base). Also the PR's output orders the
   fallback rules before `:where(.foo)` (whereas the source order is nested rule first); harmless here since
   the generated rules have higher specificity, but #1061's test expectation (`:where` first) still wouldn't
   match literally.
5. Pre-existing, out of scope: `!important` on a logical declaration is dropped when lowered (`.foo{border-start-start-radius:10px!important}` → no `!important` in the generated rules, also on master). `light-dark()` in nested declarations unchanged.
