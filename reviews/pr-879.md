# PR #879: Fix animation shorthand property without name output
**Verdict:** request changes (small). **Confidence:** high.

Author: sapphi-red. Fixes #337. Base 9e04c01 (Dec 2024); merges cleanly onto master 574eee24 (built with `build-pr.sh --on-master`). No CI has ever run on the PR (0 check runs), no comments.

## Summary
`Animation::to_css` skips every component when `animation-name` is `none`, so `animation: infinite`, `animation: 2s linear infinite`, `animation: 0s 2s`, `animation: reverse forwards paused` etc. all serialize as `animation: none` (with and without `--minify`, with and without targets). The bug is real and still on master: Chromium shows different computed `animation-duration`/`-iteration-count`/… and, when another rule supplies `animation-name`, a different animation. The PR always emits non-default components and emits `none` only when nothing else is printed. It also makes minified output use `1` (iteration count) instead of `none` for an all-default animation, and changes three existing expectations accordingly. One existing test it did not update now fails.

## Design
The fix is in the right place (the shared `Animation` serializer, used for prefixed and unprefixed shorthands and for longhands combined by `AnimationHandler`). The name-disambiguation rules (spec: "default values of other properties must be output in at least the cases necessary to distinguish an animation-name") are unchanged and still keyed on the name, so they only apply when a name is present; with name `none` nothing needs disambiguating. Fine.

The `none`→`1` minification is a separate, optional change. It is browser-equivalent (below) and saves 3 bytes per occurrence, but it's unrelated to #337, makes very common output (`animation:none`, often `!important` in reset/reduced-motion CSS) less recognizable, and is the source of the failing test. Maintainer's call; I'd suggest keeping `none` in this PR and doing `1` separately if wanted.

The repeated `if has_item { write ' ' }` blocks could be a small closure/macro; nit.

## Spec
css-animations-1 (https://drafts.csswg.org/css-animations-1/#animation):
> `<single-animation> = <time [0s,∞]> || <easing-function> || <time> || <single-animation-iteration-count> || <single-animation-direction> || <single-animation-fill-mode> || <single-animation-play-state> || [ none | <keyframes-name> ]`
> "...when serializing, default values of other properties must be output in at least the cases necessary to distinguish an animation-name that could be a value of another property, and may be output in additional cases."

All components are optional (`||`), and omitted ones take their initial values, so `animation:1` and `animation:none` both set every longhand to its initial value. css-animations-2 adds `|| <single-animation-timeline>` to the grammar; Chromium does not accept a timeline in the shorthand (`parse('animation','1s k scroll()')` → `""`).

## Changed expectations (verified in Chromium)
| test input | old expectation | PR expectation | Chromium |
|---|---|---|---|
| `animation: none` | `animation:none` | `animation:1` | `CSSStyleDeclaration` parse of both → `auto ease 0s 1 normal none running none`; computed name/count identical; equivalence: equiv |
| `animation: "none", none` | `"none",none` | `"none",1` | equivalent (second item all-initial either way) |
| `animation: none, none` | `none,none` | `1,1` | computed `none, none` / `1, 1` for both; equiv |

All three changes are meaning-preserving; they are a size choice, not a correctness fix.

## Findings
1. **should fix (test failure)**: `test_animation` fails on the PR (merged onto master): `minify_test(".foo { animation: none none }", ".foo{animation:none}")` now produces `.foo{animation:1}` (first `none` is the fill-mode, second the name; all defaults). CI never ran on the PR so this wasn't caught. Either update the expectation or (preferred) drop the `1` change.
2. **maintainer decision**: `animation:none` → `animation:1` in minified output, see Design. Corpus impact: −6 B react-spectrum S2, −9 B Bootstrap, −3 B Font Awesome; diffs in those files are exactly `animation:none`→`animation:1` (incl. one `!important`).
3. **pre-existing, not fixed (related)**: a non-default `animation-timeline` is still dropped when the name is `none`. `.a{animation:1s;animation-timeline:scroll()} .a.x{animation-name:k}` → base `.a{animation:none}`, PR `.a{animation:1s}`; Chromium: `.a.x` loses `animation-timeline: scroll()` (NOT EQUIV in both). Same reasoning as #337 (longhands matter when the name comes from another rule). Fix belongs in `AnimationHandler` (emit `animation-timeline` as a longhand after the shorthand, since Chromium doesn't accept it in the shorthand) — can be a follow-up. Also `animation:1s scroll()` → PR `animation:1s` (base `none`); Chromium rejects the input entirely, so the oracle flags the PR as a "regression", but it's the same pre-existing timeline-in-shorthand issue, not caused by the PR.
